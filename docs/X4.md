# unidex on the Xteink X4

A second build of unidex for the [Xteink X4](https://www.xteink.com) e-reader (ESP32-C3, 4.26" 800×480 e-paper,
16 MB flash, no PSRAM). It's the same firmware as the Waveshare board's, with the hardware parts swapped behind
`UNIDEX_X4` (`src/core/board.h`). This is an early port: it builds, but it hasn't been tested on an X4 yet.

The X4's hardware goes through the [FreeInk SDK](https://github.com/Free-Ink/freeink-sdk) (MIT), a git submodule in
`freeink-sdk/`: its board profile (pins), `EInkDisplay` (the SSD1677 driver and the X4's waveforms), `InputManager`
(the button ladders), `BatteryMonitor`, `SDCardManager` (SdFat, behind an `fs::FS` adapter in `src/core/sdkcard.cpp`
so the apps' file code is unchanged) and `PowerManager` (the battery latch and deep sleep). The SDK needs the pioarduino platform (Arduino core 3, ESP-IDF 5), so the
X4 build uses that while the Waveshare build stays on espressif32 6.11 (Arduino core 2). The few calls that differ
between the two cores are switched on `ESP_ARDUINO_VERSION_MAJOR`.

```sh
git submodule update --init  # once, for freeink-sdk/
pio run -e x4 -t upload      # the X4 firmware (pio run -e x4-dev: the test build)
```

The X4 shows up as a USB serial port (the C3's USB Serial/JTAG) while it's awake. Some X4s from third-party shops are
USB-locked at the factory: see CrossPoint Reader's unlock notes before flashing one.

## What's different

| | Waveshare 1.54" | Xteink X4 |
|---|---|---|
| Screen | 200×200, SSD1681 | 800×480, SSD1677 (FreeInk `EInkDisplay`), used upright; the 200×200 screens are drawn at twice the size (400×400) in the middle. Partial refreshes are the SDK's fast refresh, full ones its single-flash clean (HALF) refresh |
| Buttons | A (BOOT), B (PWR) | A = any arrow key (Left, Right, Up, Down); B = Confirm or Power; Back = hold A |
| Restart | hold both | hold Power (or Confirm) and a side key (Up or Down) |
| Wake from sleep | either button | Power, Right or Down (only those can wake the ESP32-C3) |
| SD card | SD_MMC | FreeInk `SDCardManager` (SdFat over SPI, sharing the panel's bus, CS GPIO12) |
| Clock | PCF85063 chip | the ESP32's own timer: kept through sleep, lost when the battery is cut or flat, until the next sync |
| Microphone | ES8311 | none: no Notes app |
| Battery | GPIO4 ÷2 | FreeInk `BatteryMonitor` (GPIO0 ÷2, not calibrated yet); USB sensed on GPIO20; GPIO13 keeps battery power on |
| CPU | up to 240 MHz | up to 160 MHz |

Not ported: the games' fast waveform (the SSD1681 one doesn't fit this panel), so game frames are the SDK's fast
refresh and slower. The SDK's panel sleep doesn't keep the controller's copy of the last image, so the first screen
after the board wakes is a clean (flashing) refresh rather than a partial one. The website's installer and Sync only
know the Waveshare firmware.

## Still to check on a device

- the image is upright and centred (`LEFT`/`TOP` and the row order in `src/core/display.cpp`);
- the key mapping in `src/core/input.cpp` and the battery calibration in `src/core/battery.cpp`;
- the SD card and the panel sharing the SPI bus (unidex starts the bus with MISO before the SDK's `begin()`);
- deep-sleep current with GPIO13 held high, and how far the ESP32's timer drifts in a day.
